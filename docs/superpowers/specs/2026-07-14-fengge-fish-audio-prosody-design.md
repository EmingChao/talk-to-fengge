# 峰哥 Fish Audio 人格语气编排设计

## 目标

让 Fish Audio 根据峰哥人格的表达特点生成更接近真人的情绪和语气，同时保持“克制自然”：普通回复不加标签，只有出现明确人格或话题信号时才控制语气。

所有情绪标签只存在于 TTS 内部。页面文字、LiveKit 文字转写、聊天记录和记忆系统继续使用 LLM 原始回复，不得出现 Fish Audio 标签。

## Fish Audio 官方规则

Fish Audio S2.1 模型使用方括号描述情绪和表达方式，例如：

```text
[confident] 这是个好事儿啊。
[sarcastic] 不就那么回事吗？
[calm] 这个事不能开玩笑，我跟你说实话。
[excited] 终于跑通了。
```

官方规则和建议：

- S2.1 使用 `[bracket]` 语法，S1 才使用 `(parenthesis)`。
- 句子级情绪标签通常放在句首。
- 每个句子只使用一个主情绪，避免混合冲突情绪。
- 短文本不要滥用标签，情绪变化之间应留出空间。
- `s2.1-pro-free` 与 `s2.1-pro` 使用相同模型能力。
- 情绪标签不计入 token 限制，也不会引入额外情绪处理延迟。

官方参考：

- `https://docs.fish.audio/developer-guide/core-features/emotions`
- `https://docs.fish.audio/developer-guide/models-pricing/models-overview`

## 方案选择

采用确定性规则编排，不增加第二次 LLM 或分类模型调用。

未选择 LLM 双通道输出，因为当前同一 LLM 流同时驱动页面文字和 TTS，引入结构化情绪字段会增加流式解析、标签泄漏和文字缺失风险。未选择二次情绪分类调用，因为它会增加实时对话延迟、成本和外部故障点。

规则编排器无网络依赖、无额外推理延迟，规则可以直接根据峰哥人格材料维护和测试。

## 组件边界

新增 `worker/fengge_prosody.py`，提供纯函数式的 `FenggeProsodyPlanner`：

```python
planner.decorate(text) -> decorated_text
```

该组件只负责：

- 检查回复文本中的强触发信号。
- 按优先级选择最多一个 Fish Audio 标签。
- 返回添加标签的 TTS 专用文本。
- 在无强信号、功能关闭或文本为空时原样返回。

该组件不负责：

- 修改 LLM 输出。
- 修改 LiveKit 文字转写。
- 写入聊天记录或记忆。
- 调用 Fish Audio API。
- 根据用户原始消息做额外模型推理。

`worker/fish_audio_tts.py` 在构造请求体时调用编排器，只替换请求 JSON 中的 `text`。调用者传入的字符串保持不变。

## 人格语气规则

采用以下优先级，命中高优先级后不再继续选择其他标签：

1. 严肃克制：`[calm]`
2. 明确兴奋：`[excited]`
3. 调侃反讽：`[sarcastic]`
4. 高确定性判断：`[confident]`
5. 普通交流：不加标签

### 严肃克制

用于生病、死亡、家暴、自伤、违法犯罪等需要降低娱乐化表达的话题。该规则优先级最高，即使文本中同时存在反问或调侃句式，也只使用 `[calm]`。

初始信号包括：

- 生病、重病、住院、去世、死亡
- 家暴、打人、威胁、报警
- 自杀、自伤、轻生
- 违法、犯罪、诈骗、勒索

### 明确兴奋

只用于真实成功、完成和情绪波峰，不把峰哥惯用的“这是个好事儿”自动解释为兴奋。

初始信号包括：

- 终于
- 跑通了、成功了、搞定了
- 赢了、赚了、中了

### 调侃反讽

用于一本正经的荒诞表达和明显反讽，不因为普通问句或单个问号触发。

初始信号包括：

- 不就那么回事吗
- 这不就完了吗
- 你说呢
- 面子有什么用
- 苹果用户、安卓用户、力工、魅力男孩等峰哥黑话出现在明显类比句中

### 高确定性判断

用于峰哥标志性的判断前置和辩证反转，强度低于调侃。

初始信号包括：

- 这是个好事儿啊、这不好事吗
- 我跟你说实话
- 说白了
- 你知道最惨的是什么吗

### 普通交流

没有强触发信号时不添加任何标签，让克隆音色和原始标点自然决定表达。寒暄、短回答和事实说明默认属于此类。

## 文本隔离与安全

数据流如下：

```text
LLM 原始回复 ──> 页面文字 / 聊天记录 / 记忆系统
       └──────> FenggeProsodyPlanner ──> Fish Audio 请求 text
```

编排器不得原地修改输入，也不得向公共事件发送装饰后的文本。

如果 LLM 原文已经以 Fish Audio 支持的情绪标签开头，编排器不重复添加标签，避免出现冲突控制。日志只记录选择的标签名称和文本长度，不记录完整回复内容。

## 配置

新增配置：

```env
FISH_AUDIO_PROSODY_MODE=persona
FISH_AUDIO_PROSODY_INTENSITY=subtle
```

- `FISH_AUDIO_PROSODY_MODE=persona`：启用峰哥人格规则。
- `FISH_AUDIO_PROSODY_MODE=off`：完全关闭标签，恢复原始 Fish Audio 文本。
- `FISH_AUDIO_PROSODY_INTENSITY=subtle`：只在强信号下触发。当前版本只实现该强度，其他值在启动阶段明确报错，避免配置看似生效但实际无效。

编排功能只接入 Fish Audio provider。切换到 `TTS_PROVIDER=mimo` 时继续使用原有 MiMo TTS，不经过 Fish Audio 标签编排。

## 失败处理

编排器是纯本地规则，不应抛出运行期网络错误。如果配置无效，在 Worker 启动阶段报告明确错误。

如果没有命中规则，直接使用原始文本。如果文本已经有标签或无法安全判断，则优先保持原文，不尝试猜测。编排器异常不得导致文字回复丢失；Fish Audio provider 应回退到未装饰文本并记录简短错误。

## 测试策略

新增聚焦单元测试并扩展现有 Fish Audio 测试，覆盖：

- 普通短句不加标签。
- 四类人格强信号选择正确标签。
- 严肃规则优先于兴奋、调侃和自信规则。
- 每个文本块最多添加一个主标签。
- 已带标签的文本不重复装饰。
- `off` 模式原样返回。
- 无效模式和强度在启动阶段失败。
- Fish Audio 请求体收到装饰文本，但调用者原始字符串保持不变。
- 页面、记忆和 MiMo 代码路径不引用 `FenggeProsodyPlanner`。
- 真实 Fish Audio API Key 不进入仓库。

测试不调用真实 Fish Audio API，不消耗额度。

## 完成标准

- Fish Audio TTS 能按峰哥人格规则使用官方 S2.1 方括号标签。
- 默认强度为克制自然，普通回复不强制加标签。
- 页面文字、聊天记录和记忆中不出现内部标签。
- 关闭配置后 Fish Audio 使用原始文本。
- MiMo 回切路径行为不变。
- 相关单元测试、Python 编译和敏感信息扫描通过。
